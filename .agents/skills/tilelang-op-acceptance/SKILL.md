# TileLang-Ascend 算子数值验收

## 〇、核心原则

```text
╔═══════════════════════════════════════════════════════════════════════╗
║  一条验收结论 = 数字 + 适用范围 + 对照组。                            ║
║  缺任一项，它只是「某次跑里看到了」，不是判据。                        ║
║                                                                       ║
║  - 适用范围四格必填：形 / dtype / 输入分布 / 开关状态                  ║
║  - 对照组 = 探针里一个已知-good 的用例（不过则全部结论作废）           ║
║  - 目标形排在用例表第一行；跑不动就写「未验证」，不许小形顶替           ║
╚═══════════════════════════════════════════════════════════════════════╝
```

本技能不定义新的精度阈值——**阈值体系取自 `tilelang-op-test-design/references/precision-standard.md`**。
本技能管的是那套标准**怎么被正确使用**：什么形状上、带什么对照、能不能外推。

## 1. 技能定位与支持场景

### 1.1 四种场景

| 场景 | 输入 | 你的目标 | 主要产物 |
|---|---|---|---|
| **A 首次验收** | 一个已能跑的算子 + design.md | 判它"能不能交付"，并留下可复核证据 | 验收报告（§6 模板）+ 归档目录 |
| **B 复核既有结论** | 别人或历史的"六项达标/全绿/跑通" | 判断这句话**能不能被引用**，缺什么 | 四格缺口清单 + 需补的跑数 |
| **C 目标形不达标** | 小形对、目标形错（或反之） | 按 §5.4 四步定位到"kernel / 前置件 / 分支 / 参数" | 定位结论 + 单变量证据 |
| **D 写/改判据** | 一段待写的 DoD、测试 gate、报告口径 | 把判据改写成可判定、可机械执行的形式 | 判据行 + 门禁落点 |

### 1.2 触发关键词

「验收」「精度达标」「六项/多项指标」「目标形/真形档」「全绿」「跑通」「复现」「对拍」
「DoD」「判据」「口径」「假绿」「为什么测了还是错」。

### 1.3 不做什么

- 不生成用例清单、不定阈值 → 那是 `tilelang-op-test-design`；
- 不写 kernel、不调性能 → 那是 `tilelang-op-develop` / `tilelang-perf-optimization`；
- 不合并单文件示例 → 那是 `tilelang-example-merge`，但**它的产物由本技能的 4.1 gate 守护**。

## 3. 三个尺子：先选，再报

| 尺子 | 定义 | 适用 | 陷阱 |
|---|---|---|---|
| `max_abs` | `max|a−g|` | 同一量级的同一量横向比 | 与量级绑定，跨形状不可比 |
| `rel` | `max|a−g| / max|g|` | 跨形状、跨机器比较；本项目主判据 | 单元素极值归一化，会掩盖多数元素 |
| `matched_ratio` | `mean(|a−g| ≤ atol + rtol·|g|)` | 业内通用（见 precision-standard） | 假设"误差与元素自身幅值同尺度"，深链算子可能**结构性不可达** |

### 3.1 与既有精度标准的关系（必读，避免另造概念）

`tilelang-op-test-design/references/precision-standard.md` 定义的通过条件是**双门限**：

```
(1) matched_ratio ≥ required_matched_ratio      (fp16: 0.99)
(2) max_abs_error ≤ max_abs_error_limit         (fp16: 1e-1)
```

本技能**不改这两个数**，只补充两条使用约束：

1. **深链算子要同时报 `rel`**，并在判据里写明选了哪一个、为什么。
   依据：`rel` 与 `matched_ratio` 在本项目实测**几乎不相关**——`dg` 的 `rel` 全场最好
   （2.5e-04）而 `matched_ratio` 只有 0.797；`dh0` 的 `rel` 4.6e-04 对应 0.9998。
   `matched_ratio` 高低主要反映**元素幅值分布**，不反映精度好坏。
2. **判据落地前先做可达性检查**：若算子的误差底噪由中间量决定（chunked GEMM 链、多级归约），
   则小幅值元素的允许误差 `atol + rtol·|g_i|` 可能**小于底噪**，这一列永远过不了。
   此时判据应改为 `rel`，`matched_ratio` 作诊断列。计算示例见
   `references/acceptance-protocol.md` §3.2。

> ⚠️ **不允许**在同一张表里混用两个尺子；换算时必须把 `|g|max`、长度因子等显式写出。

## 4. 十条 gate（执行顺序）

| # | Gate | 违反后果 | 机械检查 |
|---|---|---|---|
| G1 | 结论填满四格 | 结论无法被引用 | 报告模板必填项（§6） |
| G2 | 目标形排在用例表第一行 | 目标形长期只被 `isfinite` 验 | case 表结构检查 |
| G3 | 切片后逐个判连续 | JIT 直接拒：`Input tensor at index N must be contiguous` | 切片统一过 `_contig()`（§4.1） |
| G4 | 分块参数不得退化（`ceildiv>1` 用例） | 循环体只跑一次 ⇒ 假覆盖 | 日志打 `维度/块宽/块数` |
| G5 | 探针带 CONTROL 臂 | 探针的错伪装成产品的错 | 门禁统计 `CONTROL` 行，无则标 `none` |
| G6 | `isfinite` 不等于精度 | 把"跑通"当成"可用" | 报告模板强制同句给数 |
| G7 | 一张表一种口径 | 倍数是伪的 | 报告模板单一口径列 |
| G8 | 深链算子先做判据可达性检查 | 长期追一个追不到的数 | `references/acceptance-protocol.md` §3.2 |
| G9 | "替换被测段"的开关默认关 | 整链路未被验 | `assert` 默认值 + WARN |
| G10 | 不改运行中的脚本 | 解释器按字节偏移读取 ⇒ 语法错 | `ps` 前置；禁反引号 |

每条 gate 的**现象、机理、本项目的实测反例与代价**见 `references/gates-with-evidence.md`。

### 4.1 G3 的标准写法

```python
def _contig(x):
    """kernel 入参必须连续（JIT 桥 cython_wrapper.pyx:149 直接拒）。
    父张量连续不保证中轴切片连续：q[:,:,c*C:(c+1)*C,:] 在 H>1 时 stride 仍按完整 T 走
    （实测 [1,16,64,128] stride=(1048576,65536,128,1)）；H=1 时碰巧连续，故小测永远发现不了。
    H=1 时 is_contiguous() 为真，不产生拷贝，不改变已验证结果。"""
    return x if x.is_contiguous() else x.contiguous()
```

## 5. 四场景 SOP

### 5.1 场景 A：首次验收

| 步 | 动作 | 产物 / 判据 |
|---|---|---|
| A0 | 从 design.md 抄出**目标形**（B/H/T/DK/DV/C）、dtype 链、输入分布 | 四格草稿 |
| A1 | 选定尺子（§3），写清 `atol/rtol/ratio/max_abs` 来源 | 判据行 |
| A2 | 建用例表，**目标形第一行**，然后才是小形与弱配置 | case 表 |
| A3 | 每个探针先写 CONTROL 臂（已实测好的配置） | `CONTROL ... PASS` 行 |
| A4 | 跑：目标形 → 弱配置（小 H/小 T）→ 边界（非整除、NaN/Inf） | 原始日志 |
| A5 | 全量归档（日志 + 运行器本体 + 字节数清单） | `artifacts/<ts>/` |
| A6 | 按 §6 出报告，`未覆盖` 小节必须非空 | 报告 |

### 5.2 场景 B：复核既有结论（15 分钟可做完）

按顺序查五项，任一不满足就降级：

1. **四格**：这句结论的形状/dtype/输入分布/开关写了吗？没写 ⇒ 不可引用。
2. **开关**：测试里有没有"用 golden 替掉某段"的开关？默认值是什么？⇒ 有且默认开 ⇒ 该段未覆盖。
3. **口径**：同一张表里有没有混用 `max_abs` 与 `rel`？⇒ 查列名与量级是否可比。
4. **对照**：那份数字来自探针还是产品自测？探针有没有 CONTROL 臂？⇒ 无 ⇒ 结论不可引用。
5. **证据**：原始日志在哪？实例重启过吗？⇒ 只在 `/tmp` 里 ⇒ 不可复核。

输出：`可引用 / 需补跑（列出缺的跑数）/ 作废（说明哪一条不成立）`。

### 5.3 场景 D：判据改写

- 把"通过条件"改写为**失败条件**（NaN 陷阱：`rel >= 5e-3` 遇 NaN 为假 ⇒ 恒过，必须写 `not (rel < 5e-3)`）；
- 每个判据必须能回答"**谁**在**什么时候**跑它"：CI / 车 / 人工报告，三者选一；
- 判据旁边写清**未覆盖项**，不许留白。

### 5.4 场景 C：目标形不达标的四步排查

> 原则：**每步只动一个变量，且都自带对照**；判读规则在跑之前写下。

| 步 | 问题 | 手段 | 判读 |
|---|---|---|---|
| C1 | kernel 还是前置件？ | 把 golden 的中间量灌进去（`hs_override`/`a_override` 一类） | 灌了就变好 ⇒ 前置件；没变 ⇒ 往下 |
| C2 | 前置件的哪个分块参数退化了？ | 扫分块参数（`BK=64` vs `BK=128`），对 golden | 换参数就好 ⇒ 该分块循环（G4） |
| C3 | 是"数值宽度"还是"代码分支"？ | 形状变化若切换分支（如 `DV == C`），两条都得单独验 | 分支要单独覆盖 |
| C4 | 是布局/拷贝还是算法？ | 核级单元对拍：每个 kernel 单独喂已知输入，与 golden 同名中间量比 | 单 kernel PASS ⇒ 组合层或 host 胶水 |

完整走查（含四个真实案例的命令与数字）见 `references/investigation-playbook.md`。

## 6. 验收报告模板（填空，不许删节）

```markdown
## 结论
<算子> 在 <B/H/T/DK/DV/C> / <dtype> / <输入分布> / <开关状态> 下：
dq=… dk=… dv=… dbeta=… dg=… dh0=…
对照臂：CONTROL <名称> rel=… PASS

## 判据与来源
口径：rel = max_abs/|g|max（或 matched_ratio，二选一）
阈值与来源：<引用 precision-standard 或 design.md §9.3>
可达性检查：<底噪 vs 最小允许误差，见 acceptance-protocol §3.2>

## 适用范围（不填不许写上面那句）
- 形：…
- dtype：输入 / 累加 / 输出
- 输入分布：g 的量级、beta 分布、h0 是否为零
- 开关：是否替换了某段、是否开了 debug 路径

## 未覆盖（必须非空）
- 哪个形状/分支/golden 段没验，为什么

## 证据
- 归档：artifacts/<ts>/（全量日志 + 运行器本体 + MANIFEST 字节数）
- 复跑：<一条命令>
- 弱配置对照：<小形或小 H 的结果，用于说明"是形特定的还是普遍的">
```

## 7. 异常与边界

| 情形 | 处理 |
|---|---|
| 输出含 NaN/Inf | 判据写成失败条件；对特殊值做**位置敏感**比较（先比 NaN/±Inf mask，再只在有限位算误差） |
| 输入非整除（`T % C != 0`） | 由算子入口 `assert` 拒绝；测试要验"确实被拒"而不是"崩了" |
| 多 dtype | 判据按 dtype 查 `precision-standard` 表，不要全用 fp16 口径 |
| 空张量 / 退化形状 | 单独用例；不强求精度，验"不崩且形状对" |
| 实例掉线 | 以"已归档结果 + 待跑队列"记账，恢复后从队列头继续 |

## 8. 常见问题

| 症状 | 常见成因 | 处置 |
|---|---|---|
| 小形全过、目标形差 10 倍 | 分块参数退化（G4）或前置件缺陷 | §5.4 C2 |
| `matched_ratio` 长期上不去 | 判据与误差结构不匹配（G8） | 改 `rel`，留 ratio 作诊断 |
| 某个量单独很差、其余都好 | 它独占了某条分支/某个中间量 | §5.4 C1 用 golden 中间量做排除 |
| 探针报错很大但另一个测试很小 | **两者必有一个错**，先怀疑探针（G5） | 给探针加 CONTROL |
| 结论与昨天不一致 | 开关默认值、种子、形状、口径变化 | 逐项对四格 |
| 实例重启后证据没了 | 产物只落在 `/tmp` | 归档到 `artifacts/<ts>/` |
