# TileLang-Ascend 算子数值验收

本技能解决的问题：**"这个算子对了吗"这句话经常是假的**——不是有人撒谎，而是判据本身缺件。
缺的那几件很固定，所以可以做成检查表。

## 1. 何时使用

- 要写/要改一条数值判据（DoD、测试 gate、验收报告）；
- 要在真机上跑一轮并给出结论（"六项达标"、"目标形跑通"）；
- 别人（或昨天的你）给了一份"全绿"结论，而你要判断它能不能被引用；
- 排查"小形状对、目标形状不对"这类问题。

## 2. 核心原则：一条结论的三件套

> **验收结论 = 数字 + 适用范围 + 对照组。** 缺任一项，它只是"某次跑里看到了"。

| 件 | 反例形态 | 正确形态 |
|---|---|---|
| 数字 | "精度提升了 7~22 倍" | `dk: rel 1.32e-02 → 4.29e-03（同形同输入）` |
| 适用范围 | "六项 rel<5e-3" | "在 B1 H16 T8192 DK128 DV128、fp16、g 为 `-|randn|*0.5-0.05`、原生前置件下，六项 <5e-3" |
| 对照组 | "探针报 A 差 14%" | "探针在已实测好的 64 形上 PASS（3.6e-04），同一探针在 128 形上报 1.39e-01" |

## 3. 十条检查（按执行顺序）

逐条过；每条给出「怎么机械化」。

| # | 检查 | 机械做法 |
|---|---|---|
| 1 | 结论填满四格：形 / dtype / 输入分布 / 开关 | 结论行模板化；填不满不许进 DoD 表 |
| 2 | **目标形排在 case 列表第一行** | case 表第一行 = 目标形；跑不动就写"未验证"，不许小形顶替 |
| 3 | 切片后逐个 `is_contiguous()` | 在切片处过 `_contig(x)`（`x if x.is_contiguous() else x.contiguous()`）；不要只在入口对父张量做 |
| 4 | 每个 `T.serial(ceildiv(X,BX))` 都有"块数>1"的 case | 日志同时打 `X / BX / 块数` 三个数 |
| 5 | 每个探针都有已知-good 对照臂 | 探针输出打 `CONTROL name=.. rel=.. PASS|FAIL`；门禁对无 CONTROL 的腿标 `none`，其结论作废 |
| 6 | 不拿 `isfinite` 当精度 | 写"跑通"必须同句跟"数值未验"或数值 |
| 7 | 一张表只出现一种误差口径 | 换口径换列并注明；混比前先算清倍数里混了什么因子 |
| 8 | 深链算子同时报 `rel` 与 `matched_ratio` | 判据选一个并写理由，另一个作诊断列 |
| 9 | "用参考实现替掉被测件某段"的开关默认关 | 默认关；打开时 WARN，并把被替掉那段列为未覆盖 |
| 10 | 不在运行中的脚本上改动 | 改前 `ps` 确认；或跑副本；嵌在 `ssh "…"` 双引号串里的脚本**不要出现反引号** |

每条的现实反例与代价见 `references/gates-with-evidence.md`。

## 4. 三个现成工具（可直接复制到任意 run 目录）

### 4.1 example ↔ kernel 逐行对账

单文件示例是 kernel 文件的手抄副本，**必然漂移**。做成门：

```python
# 取出两边的"kernel 段"（从同一个锚点函数到文件尾/到 "# ==== Golden"），
# 归一化掉示例合法删除的 import 段与空行，然后逐行 diff；不一致 exit 1。
# 必须做正负两向证明：当前对 → SYNC-OK；故意删一行 → SYNC-FAIL + exit 1。
```

### 4.2 真机长跑取证（车）

一次"车"要解决四件事：**传的码是对的、只有一个车在跑、每条腿带对照、产物能归档**。

```bash
# 1) manifest md5：本地算、远端算、逐件比对，不一致拒跑
# 2) flock 单锁：远端 exec 9>/tmp/car.lock; flock -n 9 || exit 9
# 3) 每腿跑完统计 CONTROL 行：none / FAIL / ok(n)
# 4) 跑完把 /tmp/car_*.log 与卡片上的运行器本体一起拉回 artifacts/<ts>/
```

第 4 条尤其重要：只留退出码的"证据"在实例重启后就没了。

## 5. 排查路线（"小形对、目标形不对"专用）

按顺序，**每一步只动一个变量**，且都自带对照：

| 步 | 问题 | 手段 | 若成立 |
|---|---|---|---|
| 1 | 是 kernel 还是前置件？ | 喂 golden 的中间量（`hs_override`/`a_override` 一类） | 灌了就好 ⇒ 前置件 |
| 2 | 前置件的哪个分块参数退化了？ | 扫分块参数（如 `BK=64` vs `BK=128`），比对 golden | 换参数就好 ⇒ 该分块循环 |
| 3 | 是"宽度/长度"还是"代码分支"？ | 改形状会切换分支时（如 `DV==C`），要分别验 | 分支要单独覆盖 |
| 4 | 是布局/拷贝还是数值算法？ | 核级单元对拍（每个 kernel 单独喂已知输入） | 单 kernel PASS ⇒ 组合层 |

**判读规则在跑之前写下来**，跑完只对账，不解释。

## 6. 验收报告模板

```
## 结论
<算子> 在 <形/dtype/输入分布/开关> 下：<各项指标=值>，对照臂 <CONTROL 结果>。

## 适用范围（不填不许写上面那句）
- 形：B H T DK DV C
- dtype：输入 / 累加 / 输出
- 输入分布：g 的量级、beta 分布、是否 h0=0
- 开关：是否替换了某段、是否开了 debug 路径

## 未覆盖
- <哪个形状/分支/golden 段没验，为什么>

## 证据
- 归档目录：artifacts/<ts>/（全量日志 + 运行器本体 + MANIFEST 字节数）
- 复跑命令：<一条命令>
```

## 7. 反模式

- **用一次跑通代替一组证明**：`isfinite` 全 True ≠ 精度对。
- **小形状代替目标形状**：目标形跑不动就如实写"未验证"。
- **拿两套口径的数字相除**："改善 190×"里常混着 `|g|max` 与长度因子。
- **探针没有对照就下结论**：探针的错会伪装成产品的错。
- **改运行中的脚本**：bash 按字节偏移增量读取，插行即错位。
- **只留退出码**：产物不归档，结论无法复核。
