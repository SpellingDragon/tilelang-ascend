# 验收协议：四格、门禁、判据可达性、报告与复盘

本文件是 `tilelang-op-acceptance` 的协议层。SKILL.md 说"做什么"，本文件说"按什么规格写"。

---

## 1. 四格：一条结论的适用范围

任何一条数值结论必须能填出这四格。**填不出的一律降级为"某次跑里看到了"**。

### 1.1 形

必须写到**编译期常量级**，因为这些量会改变代码路径：

```
B=1 H=16 T=8192 DK=128 DV=128 C=64        # 目标形
T=128  → NC=2   （块数改变递推步数）
H=1    → 前导维为 1，切片"碰巧连续"，且部分误差项权重不同
DK=64  → bk_num=1，分块循环只跑一次（G4 的雷区）
DV=64  → DV==C，dkt 走 k_ab_dv 分支；DV=128 走 k_mm（分支差异）
C=64   → 决定 chunk 内矩阵尺寸
```

**写法反例**："在 8192 长度上" —— 缺 DK/DV/C/H。
**正确写法**：`B1 H16 T8192 DK128 DV128 C64`。

### 1.2 dtype

三段都要写，因为它们可以不同，且各自有独立阈值：

| 段 | 例 |
|---|---|
| 输入 | `q/k/v/do/h0 = fp16`，`g/beta = fp32` |
| 累加 | `L0C accum = fp32` |
| 输出 | `dq/dk/dv = fp16`，`dbeta/dg = fp32` |

**为什么必须写**：同一算子不同输出 dtype 要用不同的容差行（见 precision-standard 表），
`dbeta/dg` 是 fp32 输出却按 fp16 口径判，是**判据虚宽**（本项目犯过）。

### 1.3 输入分布

数值结论对输入分布敏感，尤其当算子含指数/归一化/递推：

- `g`（对数衰减）：本项目取 `-|randn|*0.5 - 0.05`，均值约 -0.45 ⇒ 块内 `exp(Σg)` 迅速衰减；
- `beta`：`sigmoid(randn)` ⇒ 集中在 0.5 附近；
- `h0`：`0` 与 `0.1·randn` 是两种不同难度（本项目早期只测前者）；
- 是否归一化（`q/k` 是否按行归一）会改变 `|g|max`，进而改变 `rel` 的可比性。

### 1.4 开关状态

把所有会**改变被测面**的开关列出来并写死取值：

| 开关 | 作用 | 必须写的取值 |
|---|---|---|
| `GDN_V3_GOLDEN_H` | 用 golden 的 `H_in`/`A` 替掉前置件 | `0`（原生）/ `1`（已替掉，该段未覆盖） |
| `GDN_V3_DK_SPLIT` | 多返回 dk 的四项 | `0` |
| `GDN_V3_ONESHOT_WRITE` | 改 dk 的写入路径 | `0` |
| `GDN_V3_DBG` | 每步 sync + 打印 | `0`（开则耗时不可测） |

## 2. 门禁三态

验收判据落到自动化门禁时，只有三态，不许出现第四种：

| 态 | 含义 | 处置 |
|---|---|---|
| **Skip** | 前置条件不满足（无设备、extra 未装） | 合法跳过，但报告中必须记 `SKIP + 原因` |
| **Fatal** | 门开了但**缺凭据**（有设备、有产物却没数据） | 直接失败。**"看起来没跑"不是 Skip 的理由** |
| **Pass/Fail** | 有数据且带对照 | 按判据判定 |

**反例**：测试里写 `try: run() except Exception: print("skip")` —— 会把真失败吞成 Skip。
正确写法：只有**具名前置条件**（如 `import onnx 失败`、环境变量未设）才 Skip，其余异常一律 Fatal。

### 2.1 非空转证明

一个"跑通了"的门，必须能证明它**真的跑过被测路径**，而不是空转：

- 用不可路由的端点/不存在的字典键跑一遍，确认门会红（负向锚）；
- 对探针：CONTROL 臂不过 ⇒ 标 `none`，其结论不得引用（本项目由车脚本自动打 `-CONTROL=none`）。

## 3. 判据可达性检查（G8）

### 3.1 问题

`matched_ratio` 的逐元素条件是：

```
|a_i − g_i| ≤ atol + rtol·|g_i|          (fp16: atol=6.10e-5, rtol=1.95e-3)
```

它隐含假设：**误差与元素自身幅值同尺度**。对"算完就舍入"的算子成立；
对**深链算子**（几十次 GEMM 串起来）不成立——误差底噪由**中间量幅值**决定，与末级元素多小无关。

### 3.2 可计算的判据：盈亏平衡幅值

设实测该量的最大绝对误差为 `B`（即误差底噪的保守估计）。则元素 `g_i` 能通过的条件是

```
atol + rtol·|g_i| ≥ B    ⇔    |g_i| ≥ g* := (B − atol)/rtol
```

其中 `g*` 称为**盈亏平衡幅值**。于是：

```
matched_ratio 可达 required_ratio  ⇔  P(|g| ≥ g*) ≥ required_ratio
```

**复算（本项目 `dk`，T=64）**：

```
B    = 1.358e-03
atol = 6.10e-05
rtol = 1.95e-03
g*   = (1.358e-03 − 6.10e-05) / 1.95e-03 = 0.665
实测 matched_ratio = 0.9626  ⇒  P(|g| ≥ 0.665) ≈ 0.96
要求 0.99 ⇒ 差 3 个百分点 ⇒ 这一列对该量结构性不可达
```

同一批数据里 `rel = 3.67e-04`（≈ fp16 ulp），说明**算子本身已到精度极限**，
不可达来自判据与误差结构不匹配，不是实现问题。

### 3.3 检查脚本（可直接用）

```python
import numpy as np

def reachability(golden, max_abs, atol=2**-14, rtol=2**-9, required=0.99):
    """返回 (g*, 实测能否达到 required, 说明)。golden / max_abs 为 numpy 或标量。"""
    g = np.abs(np.asarray(golden, np.float64)).ravel()
    if atol >= max_abs:
        return 0.0, True, "底噪低于 atol，所有元素都可能通过"
    g_star = (max_abs - atol) / rtol
    frac = float((g >= g_star).mean())
    ok = frac >= required
    return g_star, ok, (f"g*={g_star:.3f}, P(|g|>=g*)={frac:.4f}, "
                        f"{'可达' if ok else '结构性不可达'}")
```

### 3.4 处置

| 结果 | 动作 |
|---|---|
| 可达 | 按 precision-standard 的双门限判定，`rel` 作诊断列 |
| 不可达 | 判据改用 `rel`（阈值按 design.md §9.3 或历史数据定），`matched_ratio` 降为诊断列；**并在报告 §判据与来源 里引用上面的算式** |
| 边界（0.98~1.00） | 两列都报，结论写"该项为薄边界项"，并给出跨配置的摆动范围 |

> ⚠️ 不允许"把阈值调松到刚好通过"。要么给出误差结构论证，要么标薄边界项。

## 4. 报告与判定词表

### 4.1 判定只许用三个词

| 词 | 含义 | 允许的下一动作 |
|---|---|---|
| **可引用** | 四格齐、有对照、证据归档 | 可进 DoD 表 / 对外陈述 |
| **需补跑** | 结论方向可信但缺某项（缺弱配置、缺对照、缺归档） | 列出要补的具体跑数 |
| **作废** | 四格冲突、开关替掉了被测面、口径混比、或对照臂失败 | 说明哪一条不成立，不得引用 |

不允许"基本通过""差不多"——它们是不可判定的表述。

### 4.2 报告必填项

见 SKILL.md §6 模板。三个硬约束：

1. `未覆盖` 小节**非空**（没验的东西一定存在，写不出来说明没想清）；
2. `判据与来源` 必须指到文件行（precision-standard 表 or design.md §9.3）；
3. `证据` 必须给归档目录与**一条**可复跑命令。

## 5. 复盘格式：决策四元组

验收过程中每个岔路口都要留决策，格式固定：

```
决策点：<一句话>
选择：<做了什么>
理由：<支撑它的数据，必须可回溯到日志/数字>
被否方案：<当时考虑过的另一条 + 否决原因>
```

**只有"选择"没有"被否方案"的记录不是决策，是叙述**——它无法在下一次被复用。

示例（本项目）：

```
决策点：数值判据用哪个口径
选择：rel 为准，matched_ratio 作诊断列
理由：dk 的 B=1.358e-03 ⇒ g*=0.665 ⇒ 实测 P(|g|≥g*)=0.96 < 0.99，结构性不可达（§3.2）
被否方案：改 fp32 输出（改变上游消费方期望；本平台 fp32 输出受限）
```

## 6. 红线（不许做）

1. 不许把 `isfinite` 全真写成"精度达标"；
2. 不许用小形状结果顶替目标形（跑不动就写"未验证"）；
3. 不许在无 CONTROL 臂的探针结果上做归因；
4. 不许在同一张表里混两种口径；
5. 不许把"参考实现替换段"的开关默认打开；
6. 不许在运行中的脚本上改动（解释器按字节偏移读取）；
7. 不许只保留退出码而不归档日志（实例重启即证据消失）；
8. 不许调阈值来"刚好通过"。
