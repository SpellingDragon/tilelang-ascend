# 十条检查的实测反例与代价

来源：`system-one` 仓库 p2-13 GDN 反向（910B / CANN 8.5.2 / dav-2201）。
反例编号对应 `release/runs/1017-p2-13-oncard-window11-v2-acceptance/notes.md` 的条目号。
写文档、评审、或答辩时可直接引用这里的数字。

---

## 1 结论填满四格

**反例（[140]）**：连续两天引用的"六项 `rel`<5e-3"，实际带三个未写出的条件：

| 条件 | 实际取值 | 目标形要求 |
|---|---|---|
| `DK = DV` | 64（`v3t`/`ex`/`p3` 全部用 64） | 128 |
| `h0` | `0`（harness）或 `0.1·randn`（example） | 真实输入 |
| 前置件 | `GDN_V3_GOLDEN_H=1`（默认）时用 golden 的 `H_in`/`A` 替代 | 原生 `scan1`/`solve_a` |

**代价**：四个星期里目标形只被"跑通"（`isfinite`）过；真正量出错时是五项 5%~12%。

## 2 目标形排第一行

**反例（[142]→[152]）**：真形档一直排在 `T=64/256` 之后。

**代价**：错误被小形掩盖；直到把目标形单独拉出来，才发现 `DK=DV=128` 与 64 差 100×。

## 3 父张量连续 ≠ 中轴切片连续

**反例（[136]）**：

```
q.is_contiguous()            → True
q[:, :, 0:64, :].stride()    → (1048576, 65536, 128, 1)   → 非连续
q[:, :, 0:64, :]  H=1 时     → 连续（前导维为 1，stride 不参与判定）
```

JIT 桥对任何非连续入参直接抛 `Input tensor at index N must be contiguous`。

**代价**：两次上卡各烧 ~280s（首次编译 24 kernel）后失败；且"入口一次性 `.contiguous()`"被当成修复写进了笔记。

## 4 分块参数的退化值 = 假覆盖

**反例（[153]）**：`solve_a` 的 `KK^T` 是 `for i in T.serial(ceildiv(DK, BK))` 累加，relay 一直传 `BK=64`：

| DK | bk_num | 结果 |
|---|---|---|
| 64 | **1** | 正确（循环只跑 i=0，"非零列偏移拷贝"与"动态 `init`"从未执行） |
| 128 | 2 | `A` 差 **1.388e-01**，`H_in` 连带 4.307e-02 |
| 128（`BK=128`） | 1 | `A` 差 **5.961e-05**（2330× 改善） |

**代价**：测试矩阵里有 `DK=64`，于是"验过了"；真凶藏了四个星期。

## 5 探针必须自带已知-good 对照臂

**反例（[155]）**：本窗口 5 支自写探针，**4 支自身有缺陷**：

| 探针 | 自身缺陷 | 造成的错误结论 |
|---|---|---|
| 两支 `_realshape_*` | `g`/`beta` 被一并 cast 成 fp16 | 秒崩（`Buffer dtype mismatch`） |
| `_ws_cmp` | 比较的块布局未证实 | 报"`A` 差 14%"，正确解读应是"比较代码不对" |
| `_h0_ab` | 改了 `h0` 却没重算 golden | 报 `worst=4.855e-01`，实际是"比了两道不同的题" |
| `_bk_split_probe` v1 | 参照取了全宽，而 `nb=1` 只算首块 | CONTROL 报 6.0e-01 FAIL（被对照臂拦下） |

**机理**：探针的错不报自己错，它报"被测件错"。

**反面样本**：`_wide_tile_probe` 6 条 CONTROL 全 PASS 之后，一句话同时排除两个假设（`k_mm(128,128)` 无罪、fp16 落 GM 无罪），14 格最大 3.4e-04。

## 6 `finite` 不是 `accurate`

**反例（[138]）**：`isfinite` 六项全 True → 宣布"真形档跑通"；四小时后同一形量出 5%~12%。

## 7 两种口径不可混比

**反例（[140] 之前）**："改善 7~22×" 是 `T=256` 的 `max_abs` 除以 `T=64` 的归一化 `rel`，
倍数里混着 `|g|max × (T256/T64)`。同一张表里 `dv`/`dh0` **反向变大**就是信号。

## 8 逐元素 `atol+rtol·|g|` 对深链梯度可能不可达

**反例（[140]）**：fp16 容差 `2^-14`/`2^-9` 隐含"误差与输出元素自身幅值同尺度"。
`dk` 实测 `max_abs=1.358e-03`，`|g|max=3.70` ⇒ 相对全局幅值只有 3.7e-04（≈ulp）；
但对幅值 0.05 的元素，允许误差 `6.1e-05 + 1.95e-03×0.05 ≈ 1.6e-04` —— **比底噪小一个数量级**。

**结论**：这一列对深链梯度不是"再调调就能过"的指标。实测 `ratio≥0.99` 长期只有 2/6（`dv`/`dh0`）。

## 9 替换被测件某段的开关，默认必须关

**反例（[142]）**：`GDN_V3_GOLDEN_H` 默认 `"1"`，把 golden 的 `H_in`/`A` 灌进 relay，
等于把两个前置件从链路里挖掉。那一列"六项通过"验的是"给定正确中间量之后的下游链"。
它也解释了为什么 `dh0` 一直达标——`dh0` 不经 `H_in`。

## 10 不在运行中的脚本上改动

**反例（[141]）**：车跑着时给 `w11_car.sh` 插了两行 → 收尾报
`syntax error near token ')'`，且 `setsid` 被截成 `etsid`（bash 按字节偏移增量读脚本）。

**衍生**：脚本若嵌在 `ssh "…"` 的双引号串里，**反引号会被本地当作命令替换执行**，
实测报错 `CONTROL: command not found`；同理任何内层双引号必须写成 `\"`。
