# 十条 gate 的现象、机理与实测代价

本文件是 `tilelang-op-acceptance` 的证据层，编号与 SKILL.md §4 的 G1–G10 一一对应。
每条给：**现象**（你看到什么）、**机理**（为什么会这样）、**机械检查**（怎么拦）、
**实测反例**（本项目的数字与出处）、**落地**（挂到哪个门）。

引用约定：`[编号]` 指 `system-one/release/runs/1017-p2-13-oncard-window11-v2-acceptance/notes.md`
的条目号。写文档、评审、答辩时可直接引用这些数字。

环境：Ascend 910B / CANN 8.5.2 / dav-2201 / TileLang-Ascend。

---

## G1 结论必须填满四格

**现象**：报告写"六项 rel<5e-3"，被引用到 DoD 表、被写进对外口径。
**机理**：这句话为真，但它带着三个未写出的条件：

| 条件 | 当时实际取值 | 目标形要求 |
|---|---|---|
| `DK = DV` | 64（测试/示例/探针全用 64） | 128 |
| `h0` | `0`（测试）或 `0.1·randn`（示例） | 真实输入 |
| 前置件 | `GDN_V3_GOLDEN_H=1`（默认）用 golden 的 `H_in`/`A` 替代 | 原生 `scan1`/`solve_a` |

**机械检查**：报告模板（SKILL.md §6）把四格设为必填；`未覆盖` 小节非空。
**实测反例**：`[140]`。目标形因此在四个星期里只被"跑通"（`isfinite`）过；
真量出错时是五项 5%~12%。
**落地**：DoD 表每一格都必须能贴出四格，贴不出不许勾。

## G2 目标形排在用例表第一行

**现象**：用例表第一行是 `T=64`，目标形排在最后且常被注释掉。
**机理**：小形先跑是合理工程习惯，但**判据必须在目标形上**；排在后面的那个会长期只被
"能跑"覆盖。
**机械检查**：`case` 表结构检查——第一行的 `T/DK/DV` 必须等于 design.md 的目标形。
**实测反例**：`[142]→[152]`。真形档一直排在 `T=64/256` 之后；单独拉出来才发现
`DK=DV=128` 与 64 差 100×。
**落地**：CI 里加一条"目标形用例存在性"断言；缺失即 Fatal（不是 Skip）。

---

## G3 切片之后逐个判连续

**现象**：`Input tensor at index N must be contiguous`；`N` 从 0 变到 1 就说明是"逐个参数"。
**机理**：父张量连续**不保证**中轴切片连续：

```
q.is_contiguous()          → True
q[:, :, 0:64, :].stride()  → (1048576, 65536, 128, 1)  → 非连续
H=1 时切片                 → 连续（前导维为 1，stride 不参与判定）
```

JIT 桥（`tilelang/jit/adapter/cython/cython_wrapper.pyx:149`）对任何非连续入参**直接抛错**。
**机械检查**：所有落到 kernel 的切片统一过 `_contig(x)`（SKILL.md §4.1）；
`H=1` 时它不拷贝（`data_ptr` 不变），不改变已验证结果。
**实测反例**：`[136]`。两次上卡各烧 ~280 s（首次编译 24 个 kernel）后失败；
且"入口一次性 `.contiguous()`"曾被当作修复写进笔记。
**落地**：探针/测试里的切片创建处统一用 `_contig`；code review 时 grep `.contiguous()` 是否散落。

## G4 分块参数不得退化

**现象**：小形状对、目标形状错；改分块宽度就好。
**机理**：`for i in T.serial(ceildiv(X, BX))` 在 `X == BX` 时只跑一次迭代，
循环体内的路径（非零偏移、动态 `init`、跨块累加）**一次都没执行**。
**机械检查**：日志打印 `X / BX / 块数`；测试矩阵至少一个"块数 > 1"的用例。
**实测反例**：`[153]`。

| DK | BK | bk_num | 中间量 A 的误差 |
|---|---|---|---|
| 64 | 64 | **1** | 5.9e-05（对） |
| 128 | 64 | 2 | **1.388e-01**（错） |
| 128 | 128 | 1 | 5.961e-05（对，2330× 改善） |

**落地**：把"块数"写进用例表的列；缺块数 >1 的用例时该前置件判"未覆盖"。

## G5 探针必须带 CONTROL 臂

**现象**：探针报一个很大的误差，但另一个测试在同一配置下误差很小——**两者必有一个错**。
**机理**：探针的错不报自己错，它报"被测件错"。所以无对照时，"探针 FAIL" 的信息量为零，
而它看起来与真发现一模一样。
**机械检查**：探针输出打 `CONTROL name=.. rel=.. PASS|FAIL`；门禁统计 `CONTROL` 行，
无则标 `none`，`none` 的结论不得引用。
**实测反例**：`[155]`。本窗口 5 支自写探针 **4 支自身有缺陷**：

| 探针 | 自身缺陷 | 造成的错误结论 |
|---|---|---|
| 两支 `_realshape_*` | `g`/`beta` 被一并转成 fp16 | 秒崩（dtype 不匹配） |
| `_ws_cmp` | 比较用的块布局未证实 | 报"A 差 14%"，正确解读是"比较代码不对" |
| `_h0_ab` | 改了 `h0` 却没重算 golden | 报 4.855e-01（比了两道不同的题） |
| `_bk_split_probe` v1 | 参照取全宽，而 `nb=1` 只算首块 | CONTROL 报 6.0e-01（被对照臂拦下） |

**反面样本**：`_wide_tile_probe` 6 条 CONTROL 全 PASS 后，一句话同时排除两个假设
（`k_mm(128,128)` 无罪、fp16 落 GM 无罪），14 格最大 3.4e-04。
**落地**：车脚本每条腿打印 `$leg-CONTROL=none|FAIL|ok(n)`（`evidence-tooling.md` T2）。

## G6 `isfinite` 不是 `accurate`

**现象**：六项输出全部有限、无 NaN ⇒ 宣布"真形档跑通"。
**机理**：有限性只排除"发散/未初始化"，与精度无关。
**机械检查**：报告模板强制"跑通"同句给数值或写"数值未验"。
**实测反例**：`[138]`。`isfinite` 六项全 True 四小时后，同形量出 5%~12%。
**落地**：报告 review 时搜"跑通"一词，看同句有没有数。

## G7 一张表一种口径

**现象**："精度改善 7~22 倍"。
**机理**：分子是 `T=256` 的 `max_abs`，分母是 `T=64` 的归一化 `rel`；
倍数里混着 `|g|max × (T256/T64)` 两个因子。同一张表里 `dv`/`dh0` **反向变大**就是信号。
**机械检查**：表头标注口径；换口径必须新增列并注明换算因子。
**实测反例**：`[140]` 之前。该结论已作废。
**落地**：报告模板 `判据与来源` 只能填一个口径名。

## G8 深链算子的判据可达性

**现象**：某一列长期只有 2/6 通过（本项目：`matched_ratio≥0.99`）。
**机理**：`|a−g| ≤ atol + rtol·|g|` 假设"误差与元素自身幅值同尺度"。
深链算子的误差底噪由**中间量**决定。设底噪为 `B`，则元素能通过当且仅当
`|g| ≥ g* = (B − atol)/rtol`；要求 `P(|g| ≥ g*) ≥ required_ratio`。
**机械检查**：算 `g*` 与实测分位（`acceptance-protocol.md` §3.3 有脚本）。
本项复算：`B=1.358e-03, atol=6.1e-05, rtol=1.95e-03 ⇒ g*=0.665`，
实测 `P(|g|≥0.665)≈0.96 < 0.99` ⇒ **结构性不可达**。
**实测反例**：`[140]`。`rel` 与 `matched_ratio` 几乎不相关：
`dg` 的 `rel` 全场最好（2.5e-04）而 ratio 只有 0.797；`dh0` 的 `rel` 4.6e-04 对应 0.9998。
**落地**：判据选定一列并写明理由；另一列作诊断。**不许调阈值凑通过**。

## G9 "替换被测段"的开关默认必须关

**现象**：测试里有个环境变量，打开就用参考实现替掉某两个子算子，且默认是开。
**机理**：那一列验的是"给定正确中间量之后的下游链"，整链没被验过；报告若没写，
读者会以为是整链。
**机械检查**：默认值 `"0"`；打开时 `print("WARN: 本次不覆盖 <段>")`；
报告 `未覆盖` 必须列该段。
**实测反例**：`[142]`。`GDN_V3_GOLDEN_H` 默认 `"1"`；它还解释了为什么 `dh0` 一直达标
（`dh0` 不经 `H_in`）。
**落地**：`assert` 默认值；CI 里跑一次"默认配置"与"显式开启"两组，后者不得作为验收依据。

## G10 不改运行中的脚本

**现象**：车跑完后，本地脚本尾部报 `syntax error near token ')'`，且 `setsid` 被截成 `etsid`。
**机理**：bash 按**字节偏移**增量读取脚本；插入行 ⇒ 偏移错位 ⇒ 从一行中间继续解析。
**机械检查**：改动前 `ps` 确认无在跑实例；或改副本；或等它退出。
**实测反例**：`[141]`。腿的结果还在卡上，靠归档脚本补回来。
**衍生（同源）**：脚本嵌在 `ssh "…"` 双引号串里时，**反引号会被本地当作命令替换执行**
（实测 `CONTROL: command not found`）；内层双引号必须写 `\"`。
**落地**：把"车运行期间不改本地脚本"写进 run 目录的 README；改动前 `ps` 一条命令。
